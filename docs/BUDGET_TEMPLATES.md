# Tong Ledger — 30 Ready-Made Budget Plans

**Design status:** specification and seed-data plans, not validated financial advice. These are **budget allocation templates**, not visual themes, not loan templates, and not pre-filled transaction histories. Every plan can be cloned, edited, saved and assigned to a household/profile. 

## How the budget plan picker works
1. Select any of the 6 collections and preview one of 30 templates without changing personal data.
2. Enter take-home income and its period (weekly, fortnightly, monthly or custom); allocations calculate currency values using fixed-point integer cents with safe rounding and final-cent reconciliation.
3. Move category amounts with sliders, percent editing or dollar editing. Add/remove/rename/split/reorder categories; never overwrite the source preset.
4. Set starting date, rollover mode, goal priorities, which accounts contribute and optional separate budget scopes.
5. Save independent copy; transactions later count towards the relevant categories only once. Credit-card payments and cash transfers are never duplicate expenditure.
6. Templates are examples, not a promise they are appropriate for every household: show user-editable warning when essential obligations exceed the suggested percentage.

## Template integrity guarantees
- All 30 presets allocate exactly 100%.
- 6 collections × 5 unique plans.
- Categories may be nested later, but seed categories are plain user-editable labels.
- Minimum debt payments, housing and tax reserves are user responsibilities; suggested amounts do not replace actual legal liabilities.
- User can clone a template again and edit both independently.
- Always distinguish budget money from account balance; a plan never creates cash.

## Preset implementation contract
Each record contains stable id, group, name, description and category-to-percentage map. The UI shows percentages and computed amounts, and stores cloned user allocations separately from immutable seed presets. Round allocation cents by allocating remainder to last editable category; never store or sum finance values using floating point. Saved budgets must have a stable revision ID and full audit trail for later changes.
